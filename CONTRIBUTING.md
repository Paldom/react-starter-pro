# Contributing

Thanks for contributing to react-starter-pro. This is a React 19 + Vite 8 + TypeScript 6 starter template maintained by [@Paldom](https://github.com/Paldom). Agent-specific rules live in [AGENTS.md](AGENTS.md) — read it if you are using a coding agent; this file does not duplicate it.

## Dev setup

Requires Node >= 24 (enforced via `engines`) and npm.

```bash
npm ci
npm run dev
```

`npm run dev` starts Vite with MSW mocks — no backend needed; API responses are served by Mock Service Worker.

## Quality gates

All of these must pass before a PR is mergeable (CI enforces them):

```bash
npm run typecheck
npm run lint
npm test            # vitest (add -- --run for a single non-watch pass)
npm run format:check
```

Coverage is gated at 80% (`npm run test:coverage`), and mutation testing runs via Stryker (`npm run test:mutation`). Husky hooks run lint-staged on pre-commit and typecheck + tests on pre-push, so a clean local commit usually means a green CI.

## API changes (spec-first)

Never hand-edit anything under `src/shared/api/generated/**` — it is generated by Orval and CI fails if it is stale. To change the API surface:

1. Edit `openapi/openapi.yaml`
2. Run `npm run api:gen`
3. Commit the spec **and** the regenerated code together

## i18n

All user-facing strings go through `t()` — no hardcoded UI text. Every new key must be added to **both** locale files:

- `public/locales/en/common.json`
- `public/locales/hu/common.json`

## PR workflow

1. Branch off `main`
2. Make your change, keeping the gates above green
3. Open a PR — the "CI OK" check must pass before merge
4. For larger ideas, open an issue first to discuss before writing code

## Commit messages

No commit convention is enforced. Plain, descriptive messages are fine ("Fix sidebar focus trap on mobile"), one logical change per commit where practical.
